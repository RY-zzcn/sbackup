# 开发实施与验收计划

## 1. 开发阶段

### 阶段 A：基础骨架

交付：

- Go module 和目录结构；
- CLI 命令树；
- 终端 prompt 抽象；
- YAML 加载、校验和原子写入；
- SQLite migration；
- 结构化日志；
- `doctor` 基础检查。

验收：

- 非 TTY 环境不会进入交互菜单；
- 配置写入中断不会破坏原文件；
- secrets 权限过宽时拒绝执行敏感任务；
- 所有子命令具有稳定退出码。

### 阶段 B：Restic 核心备份

交付：

- 本地仓库；
- Restic 初始化；
- 目录备份；
- JSON 进度解析；
- 快照列表；
- 安全恢复；
- 任务锁；
- 保留策略；
- metadata 和 standard verify。

验收：

- 连续备份产生可恢复增量快照；
- 同一任务并发运行时第二个进程返回退出码 7；
- 恢复默认不能覆盖 `/`；
- 备份中断后下次运行可正常继续；
- 日志不包含 Restic 密码。

### 阶段 C：WebDAV、SFTP 和 S3

交付：

- rclone WebDAV adapter；
- WebDAV 交互向导；
- SFTP 和 S3 adapter；
- 网络错误分类；
- 连接测试和仓库初始化流程；
- 带宽、并发和重试设置。

WebDAV 验收矩阵：

- 通用 WebDAV；
- Nextcloud；
- OwnCloud；
- 自签名 CA；
- 401、403、404、429、507；
- 上传中断和恢复；
- 服务端限流；
- Unicode 路径；
- 低速和高延迟网络。

### 阶段 D：数据库来源

交付：

- PostgreSQL；
- MySQL/MariaDB；
- SQLite；
- 临时目录生命周期；
- dump 元数据；
- 恢复说明和导入命令提示。

验收：

- 数据库密码不出现在进程命令行；
- dump 失败时不会继续创建不完整快照；
- 任务结束后临时 dump 被清理；
- SQLite 在 WAL 模式下得到一致副本。

### 阶段 E：自动调度和通知

交付：

- systemd unit 生成；
- cron 兼容；
- maintenance timer；
- SMTP、Telegram、Webhook、Gotify、ntfy、Bark；
- 通知队列、重试、去重和恢复通知。

验收：

- 关机错过的 systemd 任务可以补跑；
- 通知服务不可达不改变备份核心结果；
- 首次失败和恢复能够正确通知；
- 相同错误不会持续刷屏；
- 通知内容中没有敏感字段。

### 阶段 F：状态上报

交付：

- report protocol 类型；
- HMAC 签名；
- outbox；
- heartbeat；
- 任务摘要同步；
- 上报测试命令和隐私设置。

验收：

- 面板离线 24 小时后事件仍可按顺序补报；
- 重复事件不会产生重复运行记录；
- 修改请求体后签名必然失败；
- 重放 nonce 被拒绝；
- 上报失败不阻止备份。

### 阶段 G：监控面板

交付：

- 初始化管理员；
- 节点和密钥管理；
- 上报 API；
- 状态首页；
- 任务历史；
- incident 状态机；
- missed/offline 判断；
- 中心通知；
- Docker Compose；
- 数据导出和备份说明。

验收：

- 成功、失败、warning、missed、offline、recovery 状态正确；
- 暂停监控后不发送告警；
- 恢复后 incident 自动关闭；
- 1,000 节点模拟心跳下保持可用；
- 管理页面具备 CSRF、登录限流和安全 Cookie；
- 面板不存在远程任务执行 API。

## 2. 测试策略

### 2.1 单元测试

- 配置校验和迁移；
- Restic JSON 解析；
- 参数构造和脱敏；
- WebDAV 错误分类；
- 保留策略；
- 通知去重；
- HMAC canonicalization；
- missed 状态计算；
- 数据库 migration。

### 2.2 集成测试

使用临时目录和容器启动：

- Restic 本地仓库；
- MinIO；
- OpenSSH SFTP；
- WebDAV 服务；
- Nextcloud 测试实例，可放入扩展 CI；
- PostgreSQL；
- MariaDB；
- Gotify 或模拟 HTTP 服务；
- 监控面板端到端上报。

### 2.3 故障注入

- 上传途中断网；
- 进程 SIGTERM；
- 磁盘写满；
- WebDAV 返回 429/507；
- Restic 仓库锁冲突；
- SQLite 数据库繁忙；
- DNS 故障；
- TLS 证书过期；
- 监控端返回 500；
- 通知端长期不可用；
- 系统时间偏差。

### 2.4 安全测试

- 路径和参数命令注入；
- 符号链接和恢复路径穿越；
- secret 日志扫描；
- HMAC 重放和篡改；
- API 请求体炸弹；
- 登录暴力尝试；
- CSRF；
- Webhook SSRF；
- 开放重定向和凭据跨域泄露；
- SQLite 导出是否包含明文密钥。

## 3. 发布标准

首个稳定版本发布前必须满足：

- 本地、SFTP、S3、WebDAV 至少各通过一种真实服务测试；
- 备份和恢复端到端测试连续通过；
- 完整仓库 check 通过；
- 终端菜单覆盖所有常用设置；
- 所有菜单操作都有等价 CLI；
- 上报可完全关闭；
- 监控面板可完全不部署；
- 客户端无常驻 HTTP 监听端口；
- 仓库密码、数据库密码和通知 Token 不出现在日志与报告中；
- 文档包含恢复演练，而不只包含备份说明。

## 4. 恢复演练验收

每种发布支持的存储至少执行：

1. 初始化仓库；
2. 备份测试目录和数据库；
3. 修改和删除部分源数据；
4. 再次备份；
5. 恢复旧快照到新目录；
6. 校验文件哈希；
7. 导入数据库到独立测试实例；
8. 执行 `restic check`；
9. 模拟监控漏报和恢复；
10. 验证失败和恢复通知。

只有“能够按文档恢复”才视为备份功能完成。

## 5. 后续增强方向

- 第二存储副本和 3-2-1 策略检查；
- 不可变对象存储和防勒索策略；
- 仓库容量趋势和异常增量检测；
- TOTP、OIDC 和 PostgreSQL 面板后端；
- Prometheus 和 Grafana 集成；
- 只读公共状态页；
- 更细粒度的文件恢复选择器，但仍保持终端交互；
- 批量导入多个独立节点的监控注册信息；
- 离线恢复介质和灾难恢复向导。
